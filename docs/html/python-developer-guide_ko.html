프로세서 API

Python을 확장하기위한 첫 번째 클래스 시민을 만드는 기능의 초기 릴리스에서 우리는 프로세서에 순수하게 초점을 맞출 것입니다. 처음에는 Python의 Controller Services를 개발할 수 없습니다. Python 기반 Processor를 사용할 수 있지만 기존 컨트롤러 서비스.

Java가 존재하는 프로세서 API는 Python 카운터파트보다 더 일반적이고 더 적은 원고입니다. Java API는 매우 다양한 가능성을 허용합니다. 내장할 수 있는 부품의 종류. 파이썬 API는 다른 한편으로는 더 좁은 범위와 원고가 있습니다. 이것에 대 한 많은 이유가 있다:

  • 더 좁은 집중된 API를 가진 성분을 위한 제일 연습을 격려하는 것이 쉽습니다.

  • 대부분의 사용 사례는 Python 기반 확장 포인트에 필요한 것을 볼 수 있습니다 (이전 스크립트 사용 기준) ExecuteScript와 같은 프로세서는 데이터 조작 및/또는 데이터의 복잡한 평가의 주위에 경향이 있습니다.

  • Python에서 Java(과 vice versa)로 통화하면 기본 메소드 호출보다 훨씬 비쌉니다. API를 통해 더 tailored 특정 사용 사례는 두 가지 프로세스 사이에 약간의 상호 작용을 허용합니다. 이는 크게 성능을 향상시킵니다.

종종, 그것은 비싼 개체를 만들 필요 하 고 그것을 사용 하 여 한 개체를 생성 대신 재사용, 그리고 그것을 던져. 처리하기 위해이 간단한 것을 만들기 위해, NiFi는 지명한 방법을 제공합니다 onScheduled. 이 방법은 프로세서에서 선택적으로 구현됩니다. 메소드가 구현되면 다음과 같이 정의됩니다.

국가 관리자

더 보기 context 객체의 매개 변수는 transform(), create(), onScheduled() 그리고 onStopped() 제품 설명 State Manager에 대한 액세스 제공 getStateManager() 방법. State Manager는 제공을 담당합니다. 저장소 및 검색 상태에 대한 간단한 API. State Manager에 대한 정보는 NiFi Developer의 가이드를 참조하십시오.

Python StateManager 객체가 반환됨 context.getStateManager() Java StateManager에 대한 액세스를 제공합니다. Python StateManager로, 상태는 Python 사전의 형태로 처리됩니다 (Java Maps와 반대). Java와 마찬가지로 StateManager는 모두 처리 할 수 있습니다. LOCAL 그리고 CLUSTER 국가.

StateManager의 메소드를 사용하여 상태에 액세스 할 수 있어야합니다. StateException은 잡을 수 있으며 Python 프로세서의 코드에서 처리됩니다. Python 개발자가 같은 방식으로 프로세서를 구현할 수 있도록 합니다. 상태 관련 오류가 발생하면, 프로세서는 혼란없이 작동을 계속할 수 있습니다. StateException이 StateManager에 의해 던지고 있지만 프로세서의 코드를 붙잡지 않는 경우 ProcessSession은 다시 압연됩니다. 오류가 기록됩니다.

아래는 StateManager를 사용하는 예 프로세서입니다. 이 예제는 프로세서가 실행되도록 가정한다. 1차 노드만, 1개의 스레드에만 있습니다.

from nifiapi.componentstate import Scope, StateManager, StateException
from nifiapi.flowfilesource import FlowFileSource, FlowFileSourceResult


class CreateFlowFile(FlowFileSource):
    class Java:
        implements = ['org.apache.nifi.python.processor.FlowFileSource']

    class ProcessorDetails:
        version = '0.0.1-SNAPSHOT'
        description = '''A Python processor that creates FlowFiles and uses StateManager.'''
        tags = ['test', 'python', 'source', 'state']

    def __init__(self, **kwargs):
        pass

    def onScheduled(self, context):
        try:
            self.state = context.getStateManager().getState(Scope.CLUSTER).toMap()
        except StateException as e:
            self.logger.warn('Failed to read processor state. ' + str(e))
            self.state = dict()

    def create(self, context):
        old_value = int(self.state.get('FlowFileNumber', '0'))
        new_value = old_value + 1
        new_state = {'FlowFileNumber': str(new_value)}
        try:
            context.getStateManager().setState(new_state, Scope.CLUSTER)
            self.state = new_state
        except StateException as e:
            self.logger.warn('Failed to save state. ' + str(e))

        return FlowFileSourceResult(relationship='success', attributes=new_state, contents=None)

종종 시간, 프로세서를 개발하는 동안, 가장 쉬운 방법은 확인하고 행동을 수정하는 것입니다 작은 tweaks 및 재 실행 데이터. 재시작없이 NiFi에서 가능합니다. 프로세서가 발견되고로드되면 프로세서의 소스 코드의 변경 사항 프로세서가 다시 시작될 때마다 효과 (또는 유효성 검사와 같은 특정 다른 이벤트 중).

포장 수준 Dependencies

하나 이상의 프로세서가 Python 패키지 안에 정의된 경우, 패키지는 정의해야 합니다. requirements.txt 모든 타사 의존성을 선언하는 파일 패키지에 어떤 프로세서에 필요한. 파일은 일반적으로 다음과 같습니다 :

my-python-package/
│
├── __init__.py
│
├── ProcessorA.py
│
├── ProcessorB.py
│
└── requirements.txt

이 방법에서는, 모든 필요조건은에서 적재될 것입니다 requirements.txt 패키지에 한 번 파일. 한 번 의존도를로드 할 필요가 없습니다. ProcessorA 및 한 번에 ProcessorB.

프로세서가 파이썬 패키지의 일부가 아닌 경우, 종속성으로 선언할 수 있습니다. dependencies 이름 * ProcessorDetails 내부 클래스. 이것은 프로세서가 달려있는 PyPI 모듈을 나타내는 문자열 목록입니다. 형식은 PyPI에 의해 예상되는 동일한 형식입니다. 이것은 그 프로세서가 패키지에 묶여야 할 필요 없이 제3자 의존성을 선언하는 편익을 제공합니다.

예를 들어, 프로세서가 필요한 것을 나타냅니다. pandas 설치, 구현 이처럼 봐:

의존성 고립

사용자가 주어진 유형의 NiFi 프로세서를 생성하는 첫 번째 시간, NiFi는 프로세서에 대한 별도의 Python env (venv)를 만들 것입니다. 이용안내 pip PyPI에서 지정된 의존도를 설치하는 것은 해당 프로세서의 적절한 Python 환경에만 설치합니다. 따라서, 1개의 가공업자의 의존은 다른 가공업자에 유효하지 않습니다.

그 이상, 프로세서의 하나의 버전의 의존은 프로세서의 다른 버전에 사용할 수 없습니다. 예를 들어, 같은 프로세서의 두 가지 다른 버전을 사용할 수 있다면, 버전 0.0.1 및 버전 0.0.2, 그 의존성 버전에 필요한 0.0.1 버전에 사용할 수 없습니다 0.0.2 버전 없음 0.0.2 또한 프로세서의 선언 그 의존도.

일부 환경, 그러나, 사용할 수 없습니다 pip 패키지 관리. 예를 들어, 또는 엄격한 보안 정책을 가진 환경, pip 사용할 수 없습니다. 그런 경우 Python 프로세서가 패키지될 수 있습니다. NiFi ARchive (NAR) 형식을 사용하여. 이것은 다음과 같은 특정 레이아웃을 가진 .zip 파일이며, 파일명 확장을 사용합니다. .nar:

my-nar-bundle.nar
+-- META-INF/
    +-- MANIFEST.MF
+-- NAR-INF/
    +-- bundled-dependencies/
        +-- dependency1
        +-- dependency2
        +-- ...
        +-- dependencyN
MyProcessor.py

개발된 프로세서 배포

프로세서가 개발되면 NiFi에서 사용할 수 있습니다. NAR 파일로 패키지 된 프로세서의 경우, NAR 파일은 NiFi에 복사해야합니다 lib/ 디렉토리 또는 구성 된 확장 디렉토리. NAR로 미리 포장되지 않은 프로세서의 경우, 프로세서는 Python 확장의 소스를 복사하여 배포됩니다. $NIFI_HOME/python/extensions 기본적으로 디렉토리. 확장자를 찾는 실제 디렉토리는 설정할 수 있습니다. nifi.properties 접두사가있는 속성을 통해 nifi.python.extensions.source.directory.· 예를 들어, 기본적으로, nifi.python.extensions.source.directory.default 설정 ./python/extensions. 그러나, 추가 경로는 대체로 추가될 수 있습니다 default 다른 값으로 속성 이름에서.

이름 * .py 디렉토리에 발견 된 파일은 파삭하고 검증 된 NiFi 프로세서 인 여부를 결정하기 위해 검사됩니다. 찾을 수 있도록, 프로세서는 유효한 부모가 있어야합니다 (FlowFileTransform, RecordTransform or FlowFileSource) 그리고 지명된 안 종류가 있어야 합니다 Java 으로 implements = ['org.apache.nifi.python.processor.FlowFileTransform'] or implements = ['org.apache.nifi.python.processor.RecordFileTransform'] or implements = ['org.apache.nifi.python.processor.FlowFileSource']· 이것은 NiFi가 자동으로 프로세서를 발견 할 수 있습니다.

참고, 그러나 프로세서 구현이 여러 파이썬 모듈로 끊어지면 해당 모듈은 기본적으로 사용할 수 없습니다. 주문하기 모듈과 함께 프로세서를 포장하려면 프로세서 및 관련 모듈은 Extensions 디렉토리의 밑에 직접 디렉토리에 추가해야합니다. 예를 들어, WriteNumber.py 파일은 NiFi 프로세서를 포함하고 또한에 달려 있습니다. ProcessorUtil.py 모듈, 디렉토리 구조는 다음과 같습니다:

NIFI_HOME/
    - python/
        - extensions/
            ProcessorA.py
            ProcessorB.py
            write-number/
                __init__.py
                ProcessorUtils.py
                WriteNumber.py

하위디렉토리에서 함께 포장함으로써 NiFi는 모듈을 서로 노출시키는 것을 알고 있습니다. 그러나, ProcessorA 모듈은 액세스가 없습니다. 으로 ProcessorUtils 모듈. 지원하다 WriteNumber 액세스 할 수 있습니다.

문제 해결

프로세서를 위해 만들어진 Python 환경은 디렉토리 구조 아래 NiFi의 작업 디렉토리에 있습니다. python/extensions/<module name>/<version>. 그래서, 예를 들면, 우리가 가공업자가 있는 경우에 MyProcessor 그 버전 0.0.1· 환경 디렉토리는 $NIFI_HOME/work/python/extensions/MyProcessor/0.0.1. 이 디렉토리는 updating에 의해 수정될 수 있습니다 가치의 nifi.python.working.directory 뚱 베어 nifi.properties.

문제 해결 목적으로, 우리는 환경 디렉토리를 삭제하고 싶습니다. 이것은 단순히 NiFi를 중지하여 수행 할 수 있습니다. 적절한 환경 디렉토리 및 재시작 NiFi.

전체를 삭제할 수 있습니다. work NiFi가 중지되는 동안 디렉토리, 이렇게하면 NiFi가 더 길게 시작할 수 있습니다. 다음으로 PyPI에서 모든 확장자의 의존도를 소스해야하며 모든 Java 확장자의 NAR 파일을 확장합니다.
